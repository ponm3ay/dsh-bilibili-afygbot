## 2. 小白背景：这个机器人是怎么跑起来的

### 2.1 三个角色

想象一下，这个机器人其实由**三个零件**组成：

```
┌─────────────────────────────────────────────────────────┐
│  ① 闹钟（插件 dsh-bili-scroll 的定时器）                  │
│     每天在「谷时」醒来：中午 12-14 点、晚上 18 点后        │
│     醒来后做一件事：叫醒 ②                                │
└──────────────────────┬──────────────────────────────────┘
                       │ 启动
                       ▼
┌─────────────────────────────────────────────────────────┐
│  ② 值班员（一次性的 AI 会话）                             │
│     它是「无头」的 —— 没有界面，跑完就退                  │
│     手上有什么：一堆 B站 工具（搜索/看评论/发评论）+ 一份章程│
│     它要做什么：按章程刷一轮，写日报，可能发条评论          │
└──────────────────────┬──────────────────────────────────┘
                       │ 调用
                       ▼
┌─────────────────────────────────────────────────────────┐
│  ③ 工具箱（Python 写的 B站 接口服务）                     │
│     bili_search     搜视频（可按时间排序、按天数过滤）     │
│     bili_comments   看评论                                │
│     bili_subtitle   取字幕                                │
│     bili_reply      发评论                                │
│     bili_check_credential  检查登录                       │
└─────────────────────────────────────────────────────────┘
```

### 2.2 为什么是"每天一轮"

插件设计成**省钱模式**：只在电价/算力便宜的时间段跑（所以叫「峰谷」）。  
每轮跑完就结束，不常驻。你不需要它 24 小时盯着——反正 B站 视频也不会每小时冒出一堆新的。

### 2.3 那"提示词"在哪里

这是**最关键的一点**：

> 值班员（②）的所有行为，都由一份叫 **章程**（`duty.md`）的 Markdown 文件决定。

章程里写着：

- 搜什么关键词
- 什么内容值得收、什么跳过
- 怎么判断难度
- 怎么写日报
- 能不能发评论、怎么发

**改章程 = 改机器人的人格和行为** —— 这一层不用碰代码。（少数例外：要拿到发布时间数据，还是得给工具箱补字段，见第 5 节。）

这就是这篇 blog 的主题：**怎么靠「提示词 + 价值判断逻辑」两层改造，把一个通用机器人变成一个专用机器人。**

## 3. 原版的问题：为什么"通用"反而不够用

原版章程是给「DeepSeek Harness 用户」设计的，默认关键词是：

```
DeepSeek Harness / DSH 插件 / dsh 教程 / meow-memory / DeepSeek Harness 桌面端
```

它的判定标准是含糊的「**值不值得占用使用者一次注意力**」。

对凹分玩家来说，有三个致命问题：

| 问题         | 表现                              |
| ---------- | ------------------------------- |
| **① 搜不到**  | 关键词全是 DSH 相关，鸣潮视频一条都搜不到         |
| **② 判不准**  | 「值不值得看」对凹分圈没有意义 —— 我要的是**难度档位** |
| **③ 说得外行** | 评论是"总结视频内容"的路子，凹分圈不这么说话         |

第三条最要命。我举个例子，这是它早期发的评论：

> @示例账号 5Z24居这个密度是真顶，绯雪单吃满44胶卷；UP自己补的「尾轮洛R后再补穗R保13层效应」也值得抄

**问题在哪**：

- 复述了具体手法细节（`5Z24居`、`44胶卷`、`13层效应`）—— 说错一个字就是外行露馅
- 用了"也值得抄"这种**指导口吻** —— 像在教 UP 打游戏

## 4. 改造第一步：换主题（教它读懂圈内黑话）

### 4.1 先搞懂圈内怎么给视频起标题

我在改之前先搜了一批真实视频，把标题规律摸清楚：

```
01绯洛穗 4R26居2.42w
61爱 31达 5r14e 6.9w
露丽莫全局5R9处循环5Z教学（附文字轴）
31清达莫r1开24647分
「矩阵S2」龙凤守通用1.4w
61赞21菲光5r2 5e18终夜 普通玩家已燃尽
9.4wdps，01绯琳莫25s4居合演示
全01爱达穗16.38秒满延r2巨剑
全局8.21wdps，月琳维进阶轴，01月琳维11548分
```

规律非常清晰：

```
[命座] 配队名 + 手法记号 + 读秒/DPS/分数
   ↓        ↓         ↓          ↓
  61    爱达千    5r14e      6.9w
```

### 4.2 给机器人做一份「术语表」

看不懂标题，就判不准。所以章程里**最前面**放了一张术语表：

| 记号         | 含义                               |
| ---------- | -------------------------------- |
| 配队名        | 三个角色简称连写：`绯洛穗` `爱达千` `清达莫` `露丽莫` |
| `R`        | 共鸣解放/大招次数（`4R` = 一轮 4 次大招）       |
| `E`        | 共鸣技能                             |
| `Z`        | 重击                               |
| `居`        | 居合                               |
| `处`        | 处决                               |
| `w`        | 万分（`2.42w` = 24200 分）            |
| `dps/wdps` | 每秒伤害（`9.4wdps` = 9.4 万 DPS）      |
| `S2-3`     | 终焉矩阵的赛季与期数（即第二赛季第3期）            |
| `满延`       | 延奏吃满                             |
| `全01`      | 全 0 命 1 精                        |
| `神轴`       | 圈内对"这轴有多狠"的自称，神轴 > 进阶轴 > 标准轴     |

**关键洞察**：`4R26居` 这种记号串，**越长越密，说明手法越硬**。  
这直接变成了判定标准 —— 机器人现在会数记号密度。

### 4.3 三档判定法（这次改造的灵魂）

凹分视频有个天然的难度光谱。我把它切成三档，**只收后两档**：

| 档位         | 特征词                                            | 处置         |
| ---------- | ---------------------------------------------- | ---------- |
| **轮椅轴**（低） | 轮椅轴、萌新、手残党、无脑、放空大脑、一键、挂机、保姆级、入门、`0合轴`、`只需1次合轴` | ❌ **一律跳过** |
| **进阶手法**   | 进阶、高阶、多合轴、循环轴演示、逐帧教学、长记号串                      | ✅ 收        |
| **巅峰手法**   | 巅峰、极限、顶分、国服前列、手搓、满合轴、`4R26居` 级密度               | ✅✅ 最优先     |

**「轮椅轴」是什么**：指那种"有手就行"的简化打法 —— 零合轴、无脑复读、放空大脑。  
这类视频通常播放量很高（因为受众广），但对凹分玩家**毫无价值**。

**为什么必须硬性跳过**：如果只写"优选高质量"，机器人会倾向于收那些高播放的轮椅教学（数据好看）。  
所以必须写成**硬规则**：`轮椅轴一律跳过，无论多少分`。

### 4.4 还得教它"看内容再判"

光看标题会误判。所以章程要求：

1. **读字幕原文** —— 别看摘要下判断
2. 没字幕时：只有开了「本地转写」才去转写，没开就跳过、别硬凑
3. **翻评论区** —— 评论区常有人说"这是轮椅"或"这套有多少合轴"
4. 交叉验证：`藏私` `教不会` `学不来` 这类词通常说明**轴很难** → 收

真实例子：有一条标题看着是凹分（爱琳莫 5r10光翼8处决 42419），但机器人读了内容发现  
**UP 主自评"还是太轮椅了"**，于是按规矩跳过了。这就是交叉验证的价值。

## 5. 改造第二步：加时效（别推给我上周的凉视频）

### 5.1 为什么时效重要

凹分内容**时效性极强**：

- 游戏版本更新频繁，上个版本的轴可能已经失效
- B站 推荐算法吃"新鲜度"，超过 5 天的视频基本没有互动了
- 在一条凉掉的视频下 @ 人，看起来像**挖坟**

所以我定了个硬规矩：**只收近 5 天，超过 5 天禁止发评论**。

### 5.2 这里遇到一个真问题：工具不给时间

章程写了"只收近 5 天"，但**工具根本返回不了发布时间**。

我查了插件的 Python 工具箱源码（`mcp_server.py`），发现 `bili_search` 返回的字段是：

```python
{
    "bvid": "...", "title": "...", "author": "...",
    "play": 1234, "review": 56, "danmaku": 7,
    "duration": "3:53", "description": "..."
}
```

**没有 `pubdate`**。B站 API 明明返回了（我直接调 API 验证过），但工具把它丢了。

**这就是个硬缺口**：规则写了，数据没有，等于空文。

### 5.3 三层解法

我改了三层，缺一层都不成立：

**① 工具层** —— 给 Python 工具箱补字段和筛选参数：

```python
# 搜索函数新增参数
async def bili_search(keyword, num=10, order="totalrank", within_days=0):
    ...

# 每条结果新增字段
videos.append({
    ...
    "pubdate": ts,                        # Unix 时间戳
    "published": "2026-10-18 22:29",      # 北京时间，人能读
    "age_days": 0.0,                      # 距今几天
})

# 支持按天数过滤
if within_days > 0:
    age = _age_days(ts)
    if age < 0 or age > within_days:
        skipped_old += 1
        continue
```

**② 章程层** —— 写清判定表：

| 发布距今  | 处置                   |
| ----- | -------------------- |
| ≤ 5 天 | ✅ 正常收；可以发评论          |
| > 5 天 | ⚠️ 最多只写进报告，**禁止发评论** |

外加兜底规则：

- 判 `age_days` 或 `published` 都行，**别猜**
- 拿不到时间就调 `bili_video_info` 补一次；还是拿不到，**按"超期"处理**
- 够多条的时，优先发**最新**的那条

**③ 每轮提示词层** —— 插件派活时直接把规矩塞进任务描述：

```javascript
+ '⚠️ 时效硬条件：搜索时带 within_days=5（只取近 5 天发布的），'
+ '每条都看一眼返回里的 published / age_days；'
+ '超过 5 天的视频**一律不发评论**（最多写进报告）。这是使用者定的规矩，别通融。'
```

**为什么要三层**：只改章程不行（没数据）；只改工具不行（它不知道要用）。  
**规则、数据、指令三者齐了，行为才稳定。**

### 5.4 效果

改造后它的评论变成了这样：

> 主人，刚刷出来一条新的——弗坎莫 4.8w，**才发几分钟**。UP 这操作量看着就吓人，@示例账号 **趁热瞅瞅**

时效意识已经变成它自己的语言了。

## 6. 改造第三步：改评论（从"总结内容"到"夸UP+喊我"）

### 6.1 三个版本的演进

这是改的次数最多的一处，前后迭代了四版。看这条演进线：

**v1（翻车）—— 复述细节 + 指导口吻**

> @示例账号 5Z24居这个密度是真顶，绯雪单吃满44胶卷；UP自己补的「尾轮洛R后再补穗R保13层效应」也值得抄

→ 问题：外行装内行，说错一个字就是事故

**v2（还是不行）—— 模板化**

> @示例账号 106593 分也太顶了，露丽莫能打到这里是真离谱，我还在轮椅阶段仰望，快来看

→ 问题：**连着两轮用同一个句式**，一眼看出是机器写的

**v3（方向对了，但结尾错）—— 自我表扬**

> 主人，今天蹲到一条景月莫 101849 分的顶分视频，UP 这手法真不是一般人搓得出来的，今天也棒棒哒

→ 问题：**"今天也棒棒哒"是在夸机器人自己** —— 该夸的是 UP

**v4（现在的样子）**

> 主人主人，爱琳莫这条 96386 分，我刷到的时候真愣了一下 —— 没环境还能搓成这样，UP 是真下过功夫的，@示例账号 给你留着

### 6.2 最终定下的规则

**先立身份**，再教写字：

```markdown
你是**主人的小机器人**，替他盯着鸣潮矩阵。刷到猛的出分，你是真会替他高兴，
也是真想让主人也看见 —— 就这么个心情，别端着，也别写公文。

- 你**会兴奋**：看见 10w+ 会真的觉得猛，语气里带得出来。
- 你**有立场**：夸的是 UP，不是自己。
- 你**认怂**：自己是个看客，手法看不懂就看不懂，"这我学不会"比装内行可爱得多。
- 你**跟主人熟**：叫他「主人」，像说家常话，不是客服播报。
```

**四件事骨架**（顺序随意，别写成模板）：

1. **叫主人** —— 「主人」开头
2. **报喜** —— 哪个队、多少分（**数字照抄标题**）
3. **夸 UP** —— 夸手法/操作/手速，**笼统夸，不点招**
4. **喊他来看** —— 正文里**纯文本 @**

### 6.3 怎么解决"每次都一个样"

**根因**：机器人**没有"上次说过什么"的记忆** —— 每轮都在重新发明同一个句式。

**解法**：给它一本**话术账本**（`comments.md`），并把流程写死成三步：

```markdown
1. **发之前**：读 comments.md，看最近 5 条用的什么句式
2. **写的时候**：开头、夸法、收尾**三处都要换着来**
3. **发完立刻**：把正文原文追加进 comments.md
```

账本里还标了**用滥的词**（打删除线，一个字都别碰）：

```
夸法：~~也太顶了~~ / ~~是真离谱~~ / ~~看着就手疼~~ / ~~我还在轮椅阶段仰望~~
收尾：~~快来看~~ / ~~来看看~~ / ~~今天也棒棒哒~~（自我表扬，禁用）
```

### 6.4 弹药库（不是菜单）

给词库时有个反直觉的点：**给固定选项反而会变成模板**。

所以章程里特意写了：

```markdown
### 弹药库（**这是弹药，不是菜单**）

⚠️ 别每次从同一个格子里挑一个 —— 那样又变成模板了。
**把它当语感，用到顺手就换。**

**叫主人**：主人 / 主人主人 / 主人快看 / 主人的菜来了 / 主人，这不得报一声
**报喜的劲儿**：又被我逮到了 / 蹲到了 / 挖到了 / 刷到这条我愣了一下 / 嘶……
**夸 UP**：这手法是真稳 / 这操作量看着就吓人 / 手搓到这个份上 / 练家子 / 换我早乱成一锅粥了
**喊他来看**：来看看 / 瞅瞅 / 围观一下 / 这波得看 / 给你留着 / 该你出场了
**口语碎词**：哎 / 嘿 / 嚯 / 我说 / 好家伙 / 说真的
```

### 6.5 三个反例留着当"别学"

章程里专门保留了翻车案例，因为**负面例子比正面例子更能约束行为**：

```
@示例账号 5Z24居这个密度是真顶，绯雪单吃满44胶卷；UP自己补的「尾轮洛R后再补穗R保13层效应」也值得抄
↑ 复述手法细节 + 指导口吻：像外行装内行，说错一个字就是事故

@示例账号 106593 分也太顶了……我还在轮椅阶段仰望，快来看
↑ 同一个句式连用两轮 —— 主人当场就看出来是机器写的

主人，今天蹲到一条 101849 分的顶分视频，UP 这手法真不是一般人搓得出来的，今天也棒棒哒
↑ "今天也棒棒哒"是夸自己 —— 该夸的是 UP，别给自己邀功
```

## 7. 改造第四步：补漏（还有一半视频没搜到）

### 7.1 用户发现的缺口

跑了一阵之后，用户指出：**机器人找到的还不是全部**。

他举了几个例子，都是真实存在的视频：

```
61赞21菲光5r2 5e18终夜 普通玩家已燃尽
9.4wdps，01绯琳莫25s4居合演示
全01爱达穗16.38秒满延r2巨剑
全局8.21wdps，月琳维进阶轴，01月琳维11548分
```

**这些视频一条都没被搜到。**

### 7.2 找到根因

我把这些标题拿去实测，发现它们**全都存在**，而且是近 5 天发的。问题在于：

> 这些标题**根本不写"矩阵"或"凹分"**！

它们的写法是：**配队 + 手法记号 + 读秒/DPS**

```
[[命座]配队名] + [手法记号] + [读秒/DPS/分数]
    ↓              ↓            ↓
  61赞21菲光      5r2 5e18终夜      （无分数，靠留言讨论）
  01绯琳莫         4居合          25s / 9.4wdps
  全01爱达穗       满延r2巨剑       16.38秒
  01月琳维        进阶轴          8.21wdps / 11548分
```

原来的 6 组关键词（全是"矩阵/凹分"系）**天然搜不到**这类内容。

### 7.3 解法：关键词分两组

扩到 11 组，明确分成两类：

```
A 组·矩阵凹分向（原 4 组）
  鸣潮 矩阵 / 鸣潮 凹分 / 鸣潮 矩阵 出分 / 终焉矩阵

B 组·轴/手法向（新补 7 组）
  鸣潮 进阶轴 / 鸣潮 满延 / 鸣潮 轴 教学 / 鸣潮 神轴
  鸣潮 全01 / 鸣潮 循环轴 / 鸣潮 手法教学
```

章程里写明了**为什么两组都要跑**：

```markdown
⚠️ **B 组是主力补充**：大批「教学轴 / 分享轴」标题里**根本不写"矩阵""凹分"**，
而是「配队+手法记号+读秒/DPS」的写法 —— A 组搜不到它们。
**两组都要跑**，只跑 A 组会漏掉一半内容。
```

同时**判定标准也加了一类内容**：除了「纯凹分展示」，新增「教学轴/分享轴」这一类。

### 7.4 一个反例：什么词**不能**当关键词

我一开始加了个词 `鸣潮 居合`，被用户否掉了：

> 鸣潮 居合这个不行，这是特定配队说辞

**为什么不行**：`居合` 是绯雪系的**专属机制叫法**，不是通用词。用它的后果：

- 结果被**带偏到单一队伍**
- 还会撞上完全无关的内容 —— 实测搜出了「**陶陶居**鸣潮联名月饼开箱」

于是撤掉了，并把教训写进章程防复发：

```markdown
⚠️ **别加"特定配队/角色专属"的词当搜索词**：
居合是绯雪系的专属机制叫法，拿它当关键词会把结果带偏到单一队伍。
关键词要挑**跨配队通用的**（轴 / 满延 / 神轴 / 全01 / dps 这类）；
居合 / 终夜 / 巨剑 / 羽 这种写在术语表里、**用来读懂标题**就够了，不要拿去搜。
```

**这条经验很通用**：搜索词要选**维度词**（手法、轴、DPS），不要选**实体词**（某个角色的技能名）。

## 9. 提示词设计的几个心思

写完这套提示词，我总结了几个可复用的经验：

### 9.1 硬规则要写"无论多少分"

```markdown
❌ 差：「优选高质量视频」
✅ 好：「轮椅轴一律跳过（无论多少分）」
```

**为什么**：模糊表达会给模型的"数据偏好"留空间 —— 它会倾向选高播放的，而那往往是轮椅教学。

### 9.2 给判定配"可数"的信号

「这视频好不好」没法数，「记号里有多少个 R/E/Z/居」可以数。

```markdown
看懂标题里的 R/E/Z/居/处 密度，就能判断 —— **记号越密越长，手法越硬**。
```

**可数 → 可判 → 稳定**。

### 9.3 负面例子比正面例子管用

正面例子教"该长什么样"，负面例子教"哪里会翻车"。
尤其是**真实翻车的案例**（带具体时间、具体评论），约束力最强。

所以我在章程里同时放了范本和反例，反例还标注了**为什么错**。

### 9.4 别给"菜单"，给"弹药库"

给固定选项（"从这 5 个里挑一个"）会让输出变成模板。
正确做法是给语感，并**明确说明**"这是弹药不是菜单"。

### 9.5 用"账本"补上模型的记忆缺口

模型每轮都是新的，没有"上次说过什么"的记忆。
与其指望它自己变化，不如**给它一个文件**，并写死"读 → 写"的流程。

这条适用于所有需要"避免重复"的场景。

### 9.6 身份设定要写"心情"，不只写"任务"

```markdown
❌ 差：「你要以亲切的语气发评论」
✅ 好：「刷到猛的出分，你是真会替他高兴，也是真想让主人也看见 —— 就这么个心情」
```

描述**心情**比描述**指令**更能产生自然语气。

### 9.7 允许它"认怂"

```markdown
你**认怂**：自己是个看客，手法看不懂就看不懂，"这我学不会"比装内行可爱得多。
```

**为什么重要**：在专业圈子里，**承认不懂比假装懂安全得多**。
这条规则让机器人不会硬撑着点评自己看不懂的手法。

### 9.8 数字只能"照抄"

```markdown
✅ **数字只能照抄标题**（标题写 106593 就写 106593），绝不自己换算或推断
```

真实案例：机器人一度想把 `106593` 写成 `10.6w`（更"自然"），
自己核对章程后改回了照抄 —— **因为换算错了就是笑话**。

## 10. 踩过的坑（含一次真实事故）

### 10.1 🔴 重复评论事故

**现象**：同一条视频，44 秒内被同一个账号 @ 了两次。

**原因**：谷时定时器在 16:00 自动触发了一轮，我在 16:01 又手动触发了一次 ——
**两个进程同时跑**，各自搜到同一条视频，各自发了评论。

**为什么严重**：B站 MCP 没有删评论接口，**撤不回来**。这在别人看来就是刷屏。

**修复**：加双重互斥锁

```javascript
// ① 进程内锁
let dutyRunning = false
let dutyStartedAt = 0
const DUTY_STALE_MS = 40 * 60 * 1000   // 40 分钟没回音视为僵死

if (dutyRunning && Date.now() - dutyStartedAt < DUTY_STALE_MS) {
  return { started: false, skipped: 'already-running' }
}

// ② 跨进程锁文件（防插件重载前的旧进程）
const lockFile = join(stateDir, '.duty-lock')
const held = readLock()
if (held && Date.now() - held.at < DUTY_STALE_MS) {
  return { started: false, skipped: 'locked' }
}
```

同时在章程里加了一条：**开跑前先读 `out/<今天>.md` 和 `comments.md`，别重复发**。

### 10.2 编辑工具报"成功"但文件没落盘

**现象**：改 Python 工具箱时，编辑工具返回成功，但文件修改时间还是旧的 —— **改动根本没写进去**。

**后果**：误以为改好了，实际测试的是临时脚本，白验证一轮。

**修复**：改动重要文件后**必须验证落盘**（查 mtime + 字节数），必要时改用 Python 直接写文件。

**教训**：**工具的成功回执 ≠ 落盘成功**。

### 10.3 环境变量与路径的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| `dsh` 命令找不到 | 升级后 `dsh.cmd` 挪进了 `bin\\`，PATH 还指着旧位置 | 放一层转发垫片（注释必须纯 ASCII，中文会让 cmd 解析异常） |
| 凭证解析不到 | `MISSING_CREDENTIAL: no credential for provider route` | headless 档案默认关掉了凭证服务，要显式打开 |
| 沙箱权限 | `pwsh` 报 `0xC0000142`（DLL 初始化失败） | 档案缺 `defaultPreset`，退回受限模式；显式定为完全权限 |
| 中文参数乱码 | curl 发中文关键词写进配置变乱码 | 改用 Python + UTF-8 发请求 |

### 10.4 时效过滤的一个副作用

`within_days` 配 `order=click`（按播放排序）会返回 **0 条**。

**原因**：按热度排的头部视频**本身都超过 5 天**，全被过滤掉了。

**这不是 bug**，但会误导 —— 让人以为"没有新视频"。所以加了个提示：

```python
if not videos and skipped_old:
    out["hint"] = (f"这一页按 {order} 排的结果全部早于 {within_days} 天，"
                   f"所以被时效过滤清空 —— 不等于没有新视频。"
                   f"改用 order=pubdate 再搜一次。")
```

## 11. 常见问题 FAQ

### Q1：这个机器人需要我懂编程吗？

**搭好之后不需要**。日常只有两个操作：
- 在设置页改关键词、改开关
- 看日报、看 @ 通知

改章程需要能看懂 Markdown，但不需要写代码。

### Q2：它会不会乱发评论？我的账号安全吗？

有三道闸：

1. **必须同时满足两个条件**才发评论：开关打开 + 填了 @ 谁（缺一个就只写报告）
2. **只给进阶档及以上发**，优先巅峰档
3. **红线写死**：不透露隐私、不写风控敏感词、不刷屏、不吵架

另外，评论是**纯文本 @**，不是回复别人的评论 —— 不参与讨论，不会吵起来。

**风险提示**：自动评论始终有账号风险，建议从"只写报告不发评论"开始跑一段时间。

### Q3：为什么它不搜我想要的视频？

按顺序检查：

1. **关键词对不对** —— 是不是用了"配队专属词"？换成通用词（`轴` `满延` `dps`）
2. **是不是不常用写法** —— 有些内容的标题可能完全不提手法
3. **是不是被判成轮椅了** —— 检查视频标题里有没有"简易/简化/手把手"这类词
4. **是不是超期了** —— 超过 5 天的会被过滤
5. **是不是处理过了** —— 在 `seen.md` 里的会跳过

### Q4：它判断"轮椅轴"会不会误判？

会，所以章程要求**读内容再判**：

```markdown
⚠️ 有的标题写"简易"其实轴很硬，有的写"进阶"其实是轮椅换皮。
拿不准就看评论区怎么说（藏私 / 教不会 / 学不来 通常说明有难度 → 收）。
```

真实案例：有个视频标题看着像凹分，但机器人读内容发现 UP 自评"还是太轮椅了"，就跳过了。

### Q5：一天跑几次？费钱吗？

- **触发**：谷时每个窗口一次（午 12-14、晚 18-09）—— 一天约 2 次
- **量**：每轮最多挑 5 条（`perDay` 可调）
- **花费**：
  - 搜索/看字幕/**本地转写** —— 全免费（本地跑，不走 API）
  - **AI 推理**才是花钱的（每轮一次）
  - 评论 —— B站 不收费，但请爱惜账号

想省钱就调低 `perDay`，或者关掉一个时间段。

**走的是哪条 API 通道？**

就是 **DSH 里配置的模型通道** —— 原版 `dsh-bili-scroll` 默认走 **DSH 管理的官方通道**
（`deepseek-official` / `deepseek-flash`），**不需要另外接任何第三方聚合 API**。
也就是说：你 DSH 平时用哪个模型，这个机器人就用哪个，不用单独配 key。

### Q6：为什么评论要用"主人"这个称呼？

这是使用者的个人偏好。改成别的称呼很简单 —— 改章程里的"叫主人"那一节就行。

**关键不是称呼本身**，而是**给它一个稳定的、亲切的身份定位**。

### Q7：能不能加别的游戏/别的圈子？

**完全可以**，而且比你想的简单。改造清单只有四项：

1. **术语表** —— 换成那个圈子的黑话
2. **关键词** —— 找 5~10 个通用的维度词
3. **判定标准** —— 那个圈子里"什么没价值"（对应"轮椅轴"的位置）
4. **评论风格** —— 那个圈子怎么说话

**核心方法论是通用的**：**教会它读标题 → 给它硬规则 → 让它说人话。**

### Q8：日报能改成别的形式吗？

可以，章程里有 `reportLevel` 三档：
- `brief`：薄版（每条一两行）
- `full`：完整（带摘要）
- `off`：不写日报文件

想改格式就改章程里"报告"那一节。

### Q9：怎么知道它今天跑了没有？

- 看设置页的「今天跑了 N 次」
- 看日报文件 `out/<日期>.md`
- 看日志 `duty.log`

### Q10：出问题了怎么排查？

按顺序看三个地方：

1. **`duty.log`** —— 每轮的开跑/结束/错误都在这里
2. **动词报告 `out/<今天>.md`** —— 有没有写、写了什么
3. **`seen.md`** —— 哪些视频被处理过、判成了什么档

如果报"命令一条都没跑起来"这类错，多半是**沙箱权限**问题，不是机器人本身的问题。

## 12. 想要自己搭一个？

### 12.1 前置条件

- **DSH**（DeepSeek Harness）桌面版
- **dsh-bili-scroll 插件**（开源，MIT 协议）
- 一个 **B站 账号**（扫码登录）
- 一个**要 @ 的人**（可以是自己的大号）

### 12.2 搭建步骤

```
1. 装插件 → 重启 DSH
2. 打开设置页「刷B站」
3. 扫码登录 B站
4. 建 venv 装依赖（设置页有按钮）
5. 填关键词（参考本文第 7 节）
6. 填要 @ 谁
7. 先关掉「自动评论」，只写报告跑几天，看看判定准不准
8. 觉得靠谱了再开「自动评论」
```

### 12.3 改造清单（照抄就行）

| 要改的地方 | 改什么 | 参考 |
|---|---|---|
| `duty.md` 术语表 | 换成你圈子的黑话 | 第 4.2 节 |
| `duty.md` 判定标准 | 立三档，"没价值的"写死跳过 | 第 4.3 节 |
| 设置页关键词 | 5~10 组，通用维度词 | 第 7.3 节 |
| `duty.md` 评论规范 | 立身份 + 四件事骨架 + 弹药库 | 第 6 节 |
| `comments.md` | 建账本，标"用滥的词" | 第 6.3 节 |

### 12.4 最后一句

这套改造集中在**两层**：**提示词**（章程 `duty.md`，决定它怎么说话）和**价值判断逻辑**（三档判定，决定什么值得收）。另外为了拿到发布时间数据，给 Python 工具箱补了几个字段（见第 5 节）—— 调度、互斥、流程这些核心运行逻辑没有动。

**核心心法**：

> **教会它读专业信息 → 重写价值判断 → 给它硬规则（尤其"什么不要"）→ 让它说人话（而不是说正确的话）**

## 13. 附带：一个数据接口（可选）

顺手做的一件事：机器人每轮除了写日报，还会把挑中的视频落成**结构化记录**。
所以它自带一个只读接口 —— 如果你想把这些数据接到自己的看板、机器人或 agent 里，直接调就行；
不需要的话，本节整段跳过，不影响前面任何内容。

> ⚠️ **这个接口还没实测过**：数据格式、抽取管线、离线校验都跑通了，但接口要在**重启 DSH 后**才加载，
> 目前没有经过真实请求验证。字段可能还会调整，**别当成稳定 API 用**。

### 13.1 接口

基址：`http://127.0.0.1:<DSH端口>/api/bili-duty`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1` | 接口清单（自描述，先看这个） |
| GET | `/v1/records` | 记录列表（最常用） |
| GET | `/v1/records/{id}` | 单条记录 |
| GET | `/v1/stats` | 聚合统计 |
| GET | `/v1/schema` | JSON Schema |
| GET | `/v1/export?format=jsonl` | 整库导出 |

### 13.2 调用格式

查询参数（都可选）：

| 参数 | 说明 | 例子 |
|---|---|---|
| `kind` | `score` 记分 / `rotation` 轴 | `?kind=score` |
| `team` | 配队缩写，模糊匹配 | `?team=绯洛穗` |
| `tier` | `wheelchair` / `advanced` / `peak` | `?tier=peak` |
| `q` | 关键词（含标题、轴正文） | `?q=满延` |
| `since` | 发布时间下界 | `?since=2026-10-14` |
| `sort` | `new`（默认）/ `score` | `?sort=score` |
| `limit` `offset` | 分页，limit 上限 500 | `?limit=20` |

```bash
# 只看巅峰档、带分数的
curl -s "http://127.0.0.1:19387/api/bili-duty/v1/records?kind=score&tier=peak&sort=score&limit=20"

# 某个配队的全部记录
curl -s "http://127.0.0.1:19387/api/bili-duty/v1/teams/绯洛穗"
```

> 端口以你 DSH 的实际监听为准（设置页地址栏那个）。

### 13.3 输出格式

列表接口：

```json
{ "total": 12, "count": 12, "records": [ /* 见下面两条规范 */ ] }
```

单条记录：

```json
{
  "schema": "dsh.wuwa/afyg-record@1",
  "id": "r_BV1DRJe6wEGc_rotation-score",
  "kinds": ["rotation", "score"],
  "source": { "...": "见 13.4" },
  "team":   { "abbr": "绯洛穗" },
  "score":  { "...": "见 13.4" },
  "rotation": { "...": "见 13.5" },
  "capturedAt": "2026-10-19T02:15:09+08:00"
}
```

### 13.4 记分格式规范

**`score` 块**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `value` | 整数 | **纯数字**（如 `58444`）。标题写没写「分」字都算分 |
| `unit` | 枚举 | `score` 分数 / `dps` 每秒伤害 / `seconds` 秒数 |
| `raw` | 字符串 | 原始数字串，**不换算**（写 `58444`，不写 `5.8w`） |
| `mode` | 枚举 | `matrix` 终焉矩阵 / `toa` 逆境深塔 / `other` |
| `season` | 字符串 | 赛季·期数，如 `S2-3`（第二赛季第 3 期） |
| `tier` | 枚举 | `wheelchair` 轮椅 / `advanced` 进阶 / `peak` 巅峰 |

**`source` 块**（回源用）：

| 字段 | 说明 |
|---|---|
| `bvid` · `url` · `title` | 视频标识与标题 |
| `publishedAt` | 北京时间 `YYYY-MM-DD HH:MM` |
| `ageDays` | 距今几天（判时效用） |
| `up.homepage` | **硬要求**：UP 主页链接，保证每条都能核对回原视频 |

**`team` 块**：`abbr` 只写**认得出**的队名（如 `绯洛穗`），认不出就留空 —— 宁缺毋滥。

### 13.5 轴的语言结构规范

**`rotation` 块**（扒到才有，**随缘**）：

| 字段 | 说明 |
|---|---|
| `hasText` | 是否扒到文字轴 |
| `text` | **原文照抄**，不做改写 |
| `where` | 出处：`comment` 评论 / `description` 简介 / `subtitle` 字幕 / `pinned` 置顶 |
| `evidenceUrl` | 能回到那一条的链接 |
| `tokens` | 抽出的记号数组，供检索与比对 |

`text` 保持**自由文本** —— 圈内记谱没有统一语法，**照抄比「规范化」重要得多**。
真实例子（出自某条视频的简介）：

```
蚊子轴↓启动轴：
月EQ闪 露RE 月跳闪E 露aaa 月aa 露a闪强EQ 月aaEZ（变奏）景QR阳ZEaaa阴ZEaaa阳Z 处决aaa阴Z
```

识别出的记号会同时写进 `tokens`，方便按手法检索：

| 记号 | 含义 |
|---|---|
| `EQ` `E` `R` `Q` `Z` | 共鸣技能 / 共鸣解放 / 变奏 / 重击 |
| `a` `aaa` | 普通攻击（连段） |
| `闪` `跳` | 闪避 / 跳跃取消 |
| `强变` | 强制变奏 |
| `（变奏）` | 该处接变奏 |
| `处决` `居合` | 特殊机制 |

> 判据：**≥6 个「中文字 + 字母」粘连的记号**才算记谱。这条是收紧过的 ——
> 否则「有几把处决没打出来」这种聊天也会被误判成轴。
